# AI 团队启示录

**简体中文** | [English](README.en.md)

**人与 AI 协作中的研发、管理与独立思考**

AI Team Reflections 记录人与 AI 协作时遇到的问题、提出的假设、尝试的方法和逐渐形成的判断。项目关注研发流程与团队管理，也关注使用 AI 后，人应该保留哪些判断与责任。

这里收录经过筛选、可以公开的思考与方法。现有流程分析和模板是讨论的起点，不是已经验证的管理答案；实践记录目前尚无试行结果。未定论的思考可以继续探索，但不能把设想写成事实或成果。

## 怎样开展思考

1. 提出具体问题，并写下自己目前的判断及理由。
2. 借助 AI 拆解问题、寻找反例、比较替代方案，区分资料与推断。
3. 由人结合实际约束做决定，并承担验证和行动责任。
4. 试行后记录结果、代价和适用边界，再决定哪些内容值得公开。

不要求每次讨论都形成文章，也不以更新数量衡量价值。真实人员、内部业务背景和未公开材料不放进本仓库；公开案例遵守隐私政策。

## 隐私是贡献的前提

**禁止提交个人隐私、凭据和保密资料。** 规则覆盖文件、Git 历史及提交身份、Issue、PR、评论、截图、附件和日志。请使用不可识别真实个人或组织的虚构示例；仅删除姓名不代表已完成匿名化。提交前必须阅读[隐私与信息提交限制](PRIVACY.md)。

仓库提供本地检查、可启用的 Git hooks 和 GitHub Actions 检查。模式检查不能证明内容可以安全公开，仍需人工审阅上下文与元数据；CI 在上传后运行，不能阻止首次泄露。

## 更新方式

按需更新，不设置自动发布计划，也不自动公开每次对话。适合公开的问题可以记录为 Issue，讨论形成建议，通过 PR 补充或修订文档；方法试行后，将可公开的观察写入实践记录。结论变化时保留原因和历史链接。

```text
实际问题或新思路 → Issue 讨论 → 文档 PR → 评审合并
                                     ↓
                             团队决定是否试行
                                     ↓
                          实践观察 → 修订方法与模板
```

每篇内容尽量说明适用场景、问题、建议做法、成本与边界、验证方式和下一步。没有实际数据时标记为建议或待验证，不把设想写成已经取得的成果。

## 文档维护

中文与英文 Markdown 是同步维护的主版本，页面提供对应语言入口。实质变更应同步两种语言；若翻译暂未完成，必须在 PR 和受影响页面明确标注。[初始 Word 文档](docs/archive/GitHub项目研发流程与团队管理分析.docx)仅作为 2026-10-23 的历史快照，不与后续 Markdown 自动同步，也不纳入双语维护范围。

初始内容包括流程分析、团队管理原则、两个管理专题及后续选题。项目当前不包含应用代码，也不表示已经配置实际业务仓库的分支保护、CI 或部署流程。

项目由 We Are a Team 演进而来，于 2026-10-24 更名为 AI 团队启示录，保留原有文档、双语结构和隐私检查。
