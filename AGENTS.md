# 项目维护约定

这是研发流程与团队管理知识库，中英文双版同步维护，Markdown 为主版本。

- 按用户要求更新，不自行创建周期性发布任务。
- 修改已有主题时优先完善现有文章，避免同义文档不断增加。
- 新文章提供语言切换入口，同步更新两种语言的 README 与选题清单。
- 保留事实、假设、建议与实际结果的区别；不得编造团队情况或管理数据。
- 外部功能和规则相关结论在必要时核对官方资料，记录链接和日期。
- docs/archive 下的 Word 文件是初始历史快照，除非明确要求，不自动重建。
- 严格遵守 PRIVACY.md：禁止提交个人信息、凭据、保密资料和含相关内容的元数据、历史、日志或附件。
- 提交身份使用 GitHub noreply 邮箱；提交前运行暂存检查，推送前检查当前分支历史。
- 隐私检查失败时先修正内容，禁止为通过检查而屏蔽规则或增加无依据的白名单。
- 对文档修改检查正文、相对链接与表格；不为低风险文字修改添加无意义测试。
- 不把本文协作约定声称为已配置的仓库保护或自动化。

## Maintenance rules in English

This is a bilingual engineering management knowledge base. Maintain Chinese and English Markdown editions together.

- Update on demand; do not create scheduled publishing without a request.
- Improve existing articles before adding duplicate topics. Link new articles in both READMEs and backlogs, with language switches.
- Distinguish facts, assumptions, proposals, and observed outcomes. Never invent team conditions or results.
- Verify external platform claims when needed and record primary-source links and dates.
- The Word archive is a historical snapshot; do not rebuild it unless explicitly requested.
- Follow PRIVACY.en.md. Never submit private information, credentials, confidential material, or metadata, history, logs, or attachments containing it.
- Use a GitHub noreply commit email. Check staged changes before committing and reachable branch history before pushing.
- Fix content when a privacy check fails; do not weaken rules or add unjustified exceptions to pass.
- Check text, links, and tables. Do not add meaningless tests for low-risk prose edits.
- Do not claim that a documented convention is an enforced repository rule or configured business automation.
